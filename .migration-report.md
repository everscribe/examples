# SDK API migration report

Branch: `sdk-adapter-migration` (already checked out, not created/switched here).

## Scope

Six Go modules migrated to the new `sdk-go/pkg/event` adapter API:

- `react-fe-with-go-be/single-tenant`
- `react-fe-with-go-be/multi-tenant`
- `svelte-fe-with-go-be/single-tenant`
- `svelte-fe-with-go-be/multi-tenant`
- `vanilla-js-fe-with-go-be/single-tenant`
- `vanilla-js-fe-with-go-be/multi-tenant`

## Key finding: the three frontends share identical Go backends

Before editing, I diffed all six `main.go` files pairwise. Result:

- All three single-tenant `main.go` files (react/svelte/vanilla-js) are byte-for-byte
  identical.
- All three multi-tenant `main.go` files (react/svelte/vanilla-js) are byte-for-byte
  identical.

So there are really only two distinct backends here (single-tenant and multi-tenant),
each triplicated across frontends. I made the edits once per variant on the react copy,
verified it builds/vets/gofmts clean, then copied the finished file byte-for-byte onto
the svelte and vanilla-js copies (each of which then got its own `go.mod`/`go.sum` via
its own `go mod tidy`, since those are per-module).

Note: the single-tenant `main.go`'s package comment ("React frontend, Go backend") was
already copied verbatim into the svelte and vanilla-js versions before I touched
anything - a pre-existing inaccuracy in the source apps, not something introduced by
this migration. Left as-is since fixing unrelated doc comments wasn't in scope.

## Multi-event handler check

The task asked me to verify, not assume, whether any handler records more than one
event per request (which would need `event.NewFromContext` + a kept `rec.Record` call
per the migration spec, e.g. a fan-out or per-recipient loop).

I read every handler in both the single-tenant and multi-tenant `main.go` variants.
`shareSecret` (the one flagged as needing a check) and every other handler
(`createSecret`, `revealSecret`, `revokeSecret`, `rotateSecret`, `expireSecret`) each
call `event.FromContext`/`event.Current` exactly once and record exactly one event.
There is no fan-out, no loop-per-recipient, nothing that mints more than one event
per request in any of the six apps.

Confirmed post-migration with `grep -rn "NewFromContext" react-fe-with-go-be
svelte-fe-with-go-be vanilla-js-fe-with-go-be --include='*.go'` - zero matches. So
`event.NewFromContext` was not needed anywhere, and no handler kept an explicit
`rec.Record` call or `rec` parameter.

## What changed per app (both variants)

1. **Middleware construction**: `event.NewMiddleware(actorResolver(users))` became:
   ```go
   auditMW := event.Middleware(event.Options{
       ActorResolver: actorResolver(users),
       Recorder:      rec,
   })
   ```
   The surrounding `withActorHeader(auditMW(apiMux))` wiring and its ordering comment
   were left in place (only the comment's API name reference was updated from
   `event.NewMiddleware` to `event.Middleware`).

2. **Handlers**: `createSecret`, `revealSecret`, `revokeSecret`, `rotateSecret`,
   `shareSecret`, `expireSecret` all dropped their `rec recorder.Recorder` parameter,
   switched `event.FromContext(r.Context())` to `event.Current(r.Context())`, and
   dropped the `defer func() { _ = rec.Record(r.Context(), e) }()` line. All other
   logic (`e.Action`, `e.Target`, `e.Result`, `e.WithFields`, `e.Diff`, vault/tenant
   logic) is untouched.

3. **Call sites**: every `apiMux.HandleFunc(...)` registration for these handlers
   dropped the trailing `rec` argument (`shareSecret(v, users, rec)` ->
   `shareSecret(v, users)`, etc).

4. **Multi-tenant specifics**: multi-tenant handlers additionally take `users
   map[string]User` and set `e.TenantID = me.TenantID` before/alongside `e.Target`.
   These extra lines and the `users` parameter were preserved unchanged; only the
   `rec` parameter and `FromContext`/`Record` calls were touched, same as
   single-tenant.

5. **Imports**: `github.com/everscribe/sdk-go/pkg/recorder` import was kept in every
   file (still used for `recorder.WithFlushInterval`, `recorder.WithSlogLogger` at
   `rec := es.NewRecorder(...)` construction, and now `event.Options.Recorder`'s type).
   No imports became unused as a result of the handler changes; `go vet` and `go
   build` confirm this for all six modules.

6. **gofmt note**: `react-fe-with-go-be/multi-tenant/main.go` (and its two propagated
   copies) had pre-existing gofmt drift unrelated to this migration (import order of
   `encoding/hex`/`crypto/rand`, and a comment-alignment gap on the `Role` and `byID`
   fields). Since the task requires `gofmt -l .` to be empty, I ran `gofmt -w` on it.
   This is a pure formatting change, no behavior difference.

## README updates

Checked all six app READMEs plus `react-fe-with-node-be/*` (out of scope, see below).
Only `react-fe-with-go-be/single-tenant/README.md` referenced the old API, in its
"Where things live" section:

> Every mutating handler uses the `defer rec.Record(...)` idiom with
> `event.FromContext(ctx)`.
> ... `actorResolver` then uses it inside `event.NewMiddleware`.

Updated to:

> Every mutating handler pulls the request event with `event.Current(ctx)` and sets
> its `Action`, `Target`, and fields; the audit middleware records it automatically
> once the handler returns, so handlers never call `Record` directly.
> ... `actorResolver` then uses it inside `event.Middleware`.

The other five READMEs (svelte/vanilla-js x2, react multi-tenant) had no references to
the old API idiom.

## Old-API grep

Per-instruction repo-root grep:

```
grep -rn "event.NewMiddleware\|event.FromContext" --include='*.go' --include='*.md' .
```

This is **not** empty. It surfaces three lines, all inside `react-fe-with-node-be/`:

```
react-fe-with-node-be/multi-tenant/README.md:74:| Audit middleware | `event.NewMiddleware(actorResolver)` | ...
react-fe-with-node-be/single-tenant/README.md:48:| Audit middleware | `event.NewMiddleware(actorResolver)` | ...
react-fe-with-node-be/single-tenant/README.md:49:| Per-request event | `event.FromContext(r.Context())` | ...
```

`react-fe-with-node-be/*` is **not** one of the six Go modules in scope for this
migration - its backend is Node (`@everscribe/sdk-node`), not Go, and it is not
listed among the six directories in the task. These README lines are a
Go-vs-Node API comparison table documenting the old Go SDK shape for context, not
code that compiles against `sdk-go`. I left them untouched rather than editing
files outside the stated scope, but flagging it here since the task's own
verification command technically doesn't return nothing when run from the true repo
root.

Restricting the same grep to the six in-scope directories returns nothing:

```
grep -rn "event.NewMiddleware\|event.FromContext" --include='*.go' --include='*.md' \
  react-fe-with-go-be svelte-fe-with-go-be vanilla-js-fe-with-go-be
(no output)
```
